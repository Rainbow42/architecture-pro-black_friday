## Как запустить финальный стенд

Все команды выполняются из директории `sharding-repl-cache`. 

```shell
cd sharding-repl-cache
```

1. Поднимаем все сервисы (сервер конфигурации, шесть узлов MongoDB, роутер, Redis и приложение):

```shell
podman compose up -d
```

Дожидаемся, пока все контейнеры станут `healthy` — статус можно посмотреть командой `podman compose ps`.

2. Настраиваем шардирование и репликацию. Скрипт инициализирует сервер конфигурации, поднимает replica set каждого шарда (по три узла), добавляет шарды в кластер и включает шардирование коллекции `somedb.helloDoc`:

```shell
./scripts/init-sharding-repl.sh
```

3. Наполняем базу тестовыми данными — 1000 документов в коллекции `helloDoc` базы `somedb`:

```shell
./scripts/mongo-init.sh
```

Если вместо Podman используется Docker, команды те же — достаточно заменить в скриптах `podman compose` на `docker compose`.

## Как проверить

Откройте в браузере http://localhost:8080 — приложение отдаст JSON с информацией о кластере:

- `mongo_topology_type: "Sharded"` — приложение работает через роутер шардированного кластера;
- `shards` — список шардов, у каждого перечислены все три узла replica set;
- `collections.helloDoc.documents_count` — общее количество документов, 1000;
- `cache_enabled: true` — кеширование через Redis включено.

Документация API доступна на http://localhost:8080/docs

Количество документов на каждом шарде и состав обеих групп репликации (1 PRIMARY и 2 SECONDARY):

```shell
./scripts/check-cluster.sh
```

Ускорение повторных запросов за счёт кеша — три запроса к эндпоинту `/helloDoc/users` с замером времени, первый выполняется дольше секунды, последующие укладываются в 100 мс:

```shell
./scripts/check-cache.sh
```

## Состав финального стенда

| Сервис | Порт на хосте | Роль |
| --- | --- | --- |
| `pymongo_api` | 8080 | приложение, образ `kazhem/pymongo_api:1.0.0` |
| `redis` | 6379 | кеш запросов приложения к MongoDB |
| `mongos_router` | 27020 | роутер, точка входа в шардированный кластер |
| `configSrv` | 27017 | сервер конфигурации, метаданные кластера |
| `shard1-1`, `shard1-2`, `shard1-3` | 27018, 27021, 27022 | replica set первого шарда |
| `shard2-1`, `shard2-2`, `shard2-3` | 27019, 27023, 27024 | replica set второго шарда |

Шард-ключ коллекции `helloDoc` — hashed по полю `name`, за счёт этого документы равномерно распределяются между двумя шардами.
